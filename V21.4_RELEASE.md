# V21.4 Release

## Verification UI
- Analysis Result is a real in-modal right-hand section, not an `<aside>`, eliminating the sidebar/CSS collision.
- Desktop layout: SEM + Full EDS on the upper row, C + O on the lower row, Analysis Result fixed on the right spanning both rows.
- C/O remain large enough for visual inspection. N/Si are removed from Verification.
- C/O ROI-to-global ratios and x-fold values remain visible.

## Score
- Displayed score remains a true 0–100 scale.
- Piecewise calibration: previous 0 -> 0, previous 85 -> 70, previous 100 -> 100.
- Decision bands: Residue >= 70, Ambiguous 60–69, Non-residue < 60.
- Frontend now recognizes calibrated backend scores and no longer subtracts 15 from them.

## Legacy points / missing assets
- Verification requests a compatibility overlay endpoint for SEM, C/O, and Full EDS visuals.
- If an old point lacks the v21 overlay assets, the backend can regenerate a cached irregular-mask visualization from the stored original SEM/C/O maps without requiring an immediate Re-analysis.
- Missing Full EDS assets can fall back to a generated C+O visualization instead of showing a blank panel.

## ROI detection
- v21.4 replaces the final fixed/dilation-only refinement with hysteresis-style local-background segmentation.
- Strong residue cores seed weaker connected regions so large irregular residues are less likely to be clipped into a small partial ROI.
- Broad shadow/background regions are restricted by polarity, contrast, analytical-area limits, and a padded candidate neighborhood.
- Local Ring is not used as a baseline.

## New Analysis
- Upload-page file-picker access is guarded so a missing ref cannot cause a client-side exception.

## Important bug fixes
- Fixed a backend candidate-area conversion bug that could abort Point analysis after candidate detection (`int(value, 1)`). This was a real cause of New Analysis failures.
- Bright and dark direct-background candidates now carry polarity metadata and are not blindly merged into the same ROI, reducing the rectangular shadow/halo failure mode.

## Validation
- Backend Python modules compile successfully with `py_compile`.
- Frontend dependency installation/build could not be executed in this offline runtime because npm registry packages were not cached; Vercel should run the normal Next.js build after the ZIP is uploaded.
